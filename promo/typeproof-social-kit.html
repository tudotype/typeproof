Caption — EN

It started with an argument about the em dash. An internal thread about one character — how it should be used, whether we should standardise — turned into a question I couldn’t put down: who is writing down each language’s typographic rules before a flood of synthetic text flattens them? Typeproof is my answer. An open-source, language-aware typographic linter: → 34 deterministic rules — quotes, dashes, spacing, diacritics — across 13 language variants → Three layers: lint → fine-tuned model → font gate (it never emits a glyph your font can’t render) → A YAML schema as the single source of truth — auditable, extensible, honest about what’s verified The deterministic core works today. Paste your own text into the live demo and watch the green diff. The part I care about most: this needs native speakers. If a rule is wrong for your language, you don’t write code — you open an issue with “what it is” vs. “what it should be”. That’s a contribution. Demo and repo in the comments ⤵

**Typeproof** — language-aware typographic correction, open source ​🔤

Straight quotes, wrong dashes, missing diacritics — fixed at the **codepoint** level, with rules that change by language. Portuguese gets « guillemets », German gets „low-high” quotes, French gets narrow no-break spaces before `!` and `?`.

`He said "hello" -- then left...` → `He said “hello” — then left…`

• 34 deterministic rules · 13 language variants · pure Python, no ML needed for the core
• Never corrupts code: URLs, backticks and paths are masked before any rule runs
• Strict mode for CI: when a change isn’t provably safe, it does nothing

**Try it live:** https://tudotype.github.io/typeproof/
**Repo:** https://github.com/tudotype/typeproof

If a rule is wrong for your language, open an issue with a before/after example — no code required. Native speakers are the whole point.
